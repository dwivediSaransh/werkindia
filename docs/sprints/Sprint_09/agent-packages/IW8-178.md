## 10. Story-specific algorithm / pseudocode

1. Load candidate and current job aggregate; reject if job is no longer open/discoverable.
2. Evaluate hard requirements, soft preferences and missing candidate fields.
3. For prepare flow, return hardBlocks/warnings/missingFields without changing application state.
4. For submit flow, validate screening answers and capture only required missing hard-gate information.
5. Recheck job state immediately before write.
6. Create CandidateApplication + immutable ApplicationSnapshot + APPLIED ApplicationEvent in one transaction.
7. Handle duplicate candidate/job unique constraint deterministically.

## 12. Security / privacy / tenancy checks

- Authorize by active persona and organisation membership when an organisation resource is touched.
- Never let a subscription/payment override candidate privacy, discoverability or block rules.
- Never write OTPs, JWT/refresh tokens, raw payment data, Aadhaar/PAN or unnecessary full candidate contact values to logs.
- Candidate search/read projections must remain free of raw contact/identity data.
- Do not trust client-provided organisation/user ids without server-side membership validation.
