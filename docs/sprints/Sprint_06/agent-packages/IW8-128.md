## 12. Security / privacy / tenancy checks

- Authorize by active persona and organisation membership when an organisation resource is touched.
- Never let a subscription/payment override candidate privacy, discoverability or block rules.
- Never write OTPs, JWT/refresh tokens, raw payment data, Aadhaar/PAN or unnecessary full candidate contact values to logs.
- Candidate search/read projections must remain free of raw contact/identity data.
- Do not trust client-provided organisation/user ids without server-side membership validation.

## 13. Observability requirements

- Correlation/trace id
- Outcome + stable error code
- Elapsed time
- Do not emit a success audit/usage event before the database transaction is committed.
- External provider retry failures should include provider event/message id where safe, never provider secrets.
